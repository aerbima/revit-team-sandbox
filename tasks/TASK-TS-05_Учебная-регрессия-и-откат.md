## TASK-TS-05 · Учебная регрессия и откат

**Зависит от:** TS-03  **Требования ТЗ:** ТР-У.03
**Файлы ТЗ:** [`Мини-ТЗ.md`](../docs/Мини-ТЗ.md), «Формат марки по умолчанию»
**Исполнитель:** dev1 · **План:** 1 ч · **Сценарии протокола:** 17
**Результат:** отработанная процедура отката влитого изменения без порчи ветки `dev`.

### Легенда

«Заказчик попросил короче марки»: формат по умолчанию — 2 знака номера вместо 3. Изменение выглядит безобидным, тесты исправляются за минуту, ревью его пропускает. После слияния тимлид проверяет кнопку «Марки помещений» на модели, где на одном уровне больше 99 помещений, и получает исключение. Это регрессия уровня S2: плагин падает на реальном объекте.

### Порядок работы

1. **PR «TASK-TS-05: формат по умолчанию — 2 знака».** Поменять `Digits` в `MarkFormat.Default` на 2, поправить тесты TS-01, добавить строку в `CHANGELOG.md`. Пройти обычный цикл и влить.
2. **Тимлид** заводит в чате карточки замечание `BUG-TS-05-01 · S2` и переносит карточку в «Возврат».
3. **PR «TASK-TS-05: откат».** На странице влитого PR нажать **Revert** — GitHub сам создаст ветку и PR с обратным коммитом. Заголовок поправить на «TASK-TS-05: откат …», в описании — ссылка на замечание.
4. CI зелёный, ревью, слияние. Ветка `dev` снова в состоянии до шага 1, история не переписана.

### Пример: откат из командной строки, если кнопки Revert нет

```bash
git switch dev && git pull                       # свежая dev
git switch -c revert/TS-05                       # ветка для отката
git revert -m 1 <sha-слияния>                    # обратный коммит; -m 1 — для коммита слияния
git push -u origin revert/TS-05                  # отправить и открыть PR в dev
```

### Готово, когда

- [ ] Изменение влито и откатано отдельным PR, `git push --force` в `dev` не использовался
- [ ] После отката тесты и поведение — как до TS-05
- [ ] Замечание `BUG-TS-05-01` закрыто ссылкой на PR отката
- [ ] Факт времени на откат записан в карточку — он нужен для оценки цены регрессии

### Подводные камни

- Нельзя «откатывать» новым ручным коммитом, переписывающим файлы назад: потеряется связь с исходным PR.
- `git reset` и `push --force` в защищённую ветку запрещены правилами — проверьте, что GitHub их отклоняет.
