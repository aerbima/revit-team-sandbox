# Протокол проверки регламента в песочнице

Как заполнять: после каждого сценария впишите дату, фактический результат и итог ✅ / ❌. Если ❌ — ссылку на issue или заметку, что поменять в регламенте. Протокол правится PR-ом в `dev` (файл защищён, одобряет тимлид) или прямо на компьютере тимлида — как удобнее.

Роли: **ТЛ** — тимлид, **D1** и **D2** — тестовые программисты (отдельные аккаунты GitHub и YouGile), **C** — Claude (ИИ-ревью и пульт).
Сценарии со знаком ★ повторяются в закрытом рабочем репозитории после подключения GitHub Pro.

## Этап A. Подготовка (до первого PR)

|---|---|---|---|---|---|---|---|---|
| 1 | Карточки из тасков | ТЛ | все | Actions → yougile-tasks → Run workflow | 5 карточек в «Бэклоге»: заголовок с кодом, ссылка на таск, чек-лист «Готово, когда», исполнитель, даты, план часов; повторный запуск не создаёт дублей. Связи на Ганте ставятся вручную по `tasks/00_Порядок-и-зависимости.md` | | | |
| 2 ★ | Защита веток | D1 | — | `git push origin dev` с локальным коммитом; затем PR с заведомо красным CI | Push отклонён. В PR кнопка Merge недоступна, пока проверки не зелёные и нет одобрения | | | |

## Критерии готовности к подключению реальных программистов

- [ ] Все 20 сценариев ✅ или ❌ с принятым решением (поправка регламента или осознанный отказ)
- [ ] Ни одного ручного шага, о котором не написано в регламенте
- [ ] Время тимлида на одну задачу (ревью + проверка в Revit) записано — это база для планирования
- [ ] Сценарии ★ повторены в закрытом репозитории с GitHub Pro
